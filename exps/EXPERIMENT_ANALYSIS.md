# SingleController 异步 GRPO：TIS 与 Score Centering 实验分析

本文汇总两批实验的结果：Qwen3.5-9B-Base（7 组）和 Qwen3-8B-Base（6 组）。所有数据来自各实验的 TensorBoard 日志（`logs/<run 名>/exp_*`），W&B project 分别是 `nemorl-sc-study` 和 `nemorl-sc-study-qwen3-8b`。配置在 `examples/configs/recipes/llm/` 和 `exps/`。

## 1. 摘要

1. **lag 4 + TIS（没有 score centering）在两个模型上都会崩溃。** Qwen3.5 的 baseline 约在第 100 步、Qwen3-8B 的 exp2 约在第 150 步，reward 掉到 0，生成长度顶到 8192，策略熵升到约 8.7，之后不再恢复。
2. **加 score centering（SC）能延缓或避免这种崩溃。** Qwen3.5 的 SC32 + TIS 崩溃推迟到约第 253 步，Qwen3-8B 的 SC32 + TIS（exp3）推迟到约第 450 步以后才接近崩溃（最后 100 步 reward 0.045）；SC128 + TIS（exp4）在 500 步内没有崩溃（最后 100 步 reward 0.345）。
3. **TIS 关闭的 SC 实验最稳。** 在 4 组 TIS 开/关的配对里，TIS 关的最后阶段 reward 都不低于 TIS 开的，其中 2 组差距很大（SC32：0.415 对 0.000；SC32 + top-p：0.422 对 0.157），另外 2 组差距较小（Qwen3.5 SC128：0.372 对 0.288；Qwen3-8B SC128：0.376 对 0.345）。
4. **top-k 在 TIS 开时越大越好；TIS 关时没有单调规律。** TIS 开：SC128 + TIS 的最后 100 步 reward（Qwen3.5：0.288；Qwen3-8B：0.345）明显高于 SC32 + TIS（0.000；0.045）。TIS 关：Qwen3.5 上 SC32（0.415）反而比 SC128（0.372，只跑了 392 步）稳。
5. **top-p 0.97 没有看到明确收益。** Qwen3.5 TIS 开时比不加 top-p 的 SC32 + TIS 好（0.157 对 0.000），但不如 SC32（TIS 关）；TIS 关时和不加 top-p 的结果接近。
6. **lag 0（完全同步）不崩溃，但 reward 也在衰减**（0.51 降到 0.185），所以 reward 的衰减不能全部归因于训练/推理失配。
7. **TIS 和 score centering 在数学上不冲突，但作用重叠。** TIS 开且未截断时，centering 修正量约为 0；训练后期失配变大后，它才变成 TIS 关时的 10%～20%。详见第 5 节。
8. **工程上，补丁加 `flat_logprobs` 把 score centering 的步耗时从 340～470 秒降到约 140 秒**，数值不变。

> 所有结论基于每个配置一个种子、训练集上的 reward（没有留出集评测），请按第 7 节的限制理解。

### 3.4 失配指标观察
- **早期失配很小**：lag 4 时前 100 步 `gen_kl_error` 约 1e-3，`token_mult_prob_error` 中位数约 1.02。
- **后期明显恶化**：第 150 步之后 `gen_kl_error` 常达 1e-2～1e-1，最大值可到 1～20；`is_oob_ratio`（被 TIS 截断的 token 比例）最高约 1%。
- **lag 0 的失配约小一个数量级**：`gen_kl_error` 约 4e-4～9e-4，`token_mult_prob_error` 约 1.006～1.013，所以 lag 4 的失配主要来自版本滞后，不是数值精度。
- **崩溃的形态**：reward 掉到 0，生成长度顶满 8192，策略熵升到 8.1～8.9，`grad_norm` 归零。Qwen3.5 SC32 + TIS 崩溃后，`head_mass` 掉到 0.28～0.32（分布变平）。
- **`token_mult_prob_error` 的均值被极少数离群 token 主导**（最大值可到 1e7 以上），所以文中一律使用窗口中位数。

## 4. 分析

### 4.1 版本滞后与崩溃
- Qwen3-8B 的 exp1（lag 0）和 exp2（lag 4）只有滞后不同：exp2 在 150 步前后崩溃，exp1 到 500 步都没有崩溃。lag 4 的步耗时约 120 秒，lag 0 约 200 秒，吞吐约快 1.6 倍，但稳定性明显更差。
- 但 lag 0 的 reward 也从 0.51 降到 0.185，且策略熵很低（0.06～0.14）。所以 reward 的衰减不能只归因于失配，策略熵塌缩、响应长度变化（后期出现 1300 token 的窗口）等因素同样存在，这次实验没有区分它们。

### 4.2 score centering 的作用
- 在 TIS 开、lag 4 的条件下，加 SC 后崩溃明显推迟或消失：Qwen3.5（baseline 100 步 → SC32 + TIS 253 步 → SC128 + TIS 437 步），Qwen3-8B（exp2 150 步 → exp3 末期接近崩溃 → exp4 无崩溃）。
- 这与理论一致：SC 通过减去采样分布下的期望得分，去掉了训练/采样失配带来的"把策略拉向采样分布"的漂移项。

### 4.3 TIS 开关
4 组配对中 TIS 关的最后阶段 reward 都不低于 TIS 开（见摘要第 3 点）。结合第 5 节，一个合理的解释（假设，没有消融实验证明）是：TIS 开着且未截断时 centering 基本被抵消，实际在运行"TIS + 很小的修正"，行为接近没有 SC 的 baseline，同时 TIS 的重尾权重引入方差和截断偏差。

### 4.4 top-k 和 top-p
- top-k：TIS 开时 128 明显好于 32；TIS 关时 Qwen3.5 上 32 更稳，Qwen3-8B 上只测了 128。头部覆盖 `head_mass` 差别很小（0.99 对 0.999），所以更大的 k 带来的精度提升有限，而代价是数据量和生成开销按 k 线性增加。
- top-p：没有看到稳定收益，TIS 关时和不加 top-p 接近。开 top-p 时 `head_mass` 恒为 1（回放使尾部为 0，是设计上的必然，不是异常），`grad_rms_off` 也更小。

### 4.5 失配随训练的变化
第 5.3 节的指标显示：训练后期失配增大，TIS 的影响变大，同时 TIS 开时 centering 的修正量也变大。

## 5. 理论与实现核对

### 5.1 目标函数与代码
group + TIS + SC 的目标，其梯度为 `A_i[w_y·s_y − Σ_v q_v·w_v·s_v]`，与代码一致：
- 采样 token 项：`importance_weights * clip_loss`，权重是 `clamp(exp(prev_logprobs − generation_logprobs), 0, 2)`。
- 中心化项：TIS 头部质量 `clamp(p, lo·q, hi·q) = q·clamp(p/q, lo, hi)`，尾部用 `α·p`（`α = clamp(1, lo·ρ, hi·ρ)`）建模，再利用 `Σ_v p_v·s_v = 0` 折回头部，系数是 `c_v = q·w_v − α·p_v`。梯度与公式相同，损失标量不同。
- 符号、`sg`（detach）、`A` 的广播都一致。
- **与公式的差别**：归一化用全局 token 平均（`token_level_loss: true`），而公式是 `(1/G)Σ(1/T_i)Σ_t`；词表求和是 top-k 头部精确加尾部近似（开 top-p 回放时精确）。

### 5.2 PPO clipping 在 SingleController 里是空的
- 每个 rollout batch 只做一次优化（校验器要求 `num_prompts × num_generations == train_global_batch_size`），旧版 GRPO / PPO 训练器直接拒绝 score centering。
- PPO 的 ratio 分母 `prev_logprobs` 是训练时用当前权重重新算的，不是 rollout 的旧策略，所以即使 lag 为 4，ratio 也恒为 1。日志里 5 个实验的 `probs_ratio` 最小/最大都是 1.000000，`probs_ratio_clamped` 也是 1。
- 版本滞后只体现在 TIS 权重 `w` 上，所以**在异步里真正限制陈旧数据影响的只有 TIS**。
- 如果以后放开多步更新，clip 会触发，centering 项独立于 clip，期望梯度不再为 0，需要重新定义修正；目前代码没有显式断言。

- **一致性检查**：`center_l1_off` 与 `weight_dev` 几乎相等。这是代码的必然结果：不开 TIS 时 centering 向量恰好等于 `q − p`，`weight_dev` 就是 `‖q−p‖₁`，说明尾部系数 ρ 等细节实现正确。
- **TIS 开时 centering 近似被抵消**：前 100 步 `center_l1_on / off` 只有约 1.5%，因为没有 token 被截断，IS 加权后的得分期望本来就是 0。
- **后期不能再忽略**：失配变大后，这个比例升到 9%～22%，`grad_rms_diff / grad_rms_off` 升到 0.3～0.58。也就是说训练后期开关 TIS 对更新的影响达到三分之一到一半。
- 这些指标在 exp1、exp2（无 SC）里不存在。

## 6. 工程发现

### 6.1 score centering 变慢的原因与补丁
- 现象：开 top-128 后步耗时是 baseline 的约 10 倍，vLLM 所在节点的 GPU 利用率接近 0，两个 vLLM actor 各占满一个 CPU 核。
- 抓到的栈：`AsyncLLM.output_handler → LogprobsProcessor._update_sample_logprobs → convert_ids_list_to_tokens → tokenizer.decode`。vLLM 对每个位置的每个 top-k 候选都解码成字符串，这是单线程 GIL 工作；而我们只用 id 和 logprob，字符串被丢弃。
- PR #5034（向量化提取）只覆盖提取部分，不解决这个瓶颈；它自己说明候选解码属于 vLLM 上游，不在该 PR 里。
- 补丁 `skip_logprobs_candidate_detokenize`：仅对被 capture 且请求了 logprobs 的调用，让 `LogprobsProcessor` 不拿 tokenizer；正文解码不受影响。1 节点 A/B：稳态步耗时 425 秒 → 79 秒，数值一致。
- 正式实验中，Qwen3.5 的 score centering 步耗时从 340～470 秒降到约 140 秒。
- **vLLM worker 实际用容器里的 `/opt/nemo-rl`**，所以补丁文件要用 bind mount 覆盖进去；这些补丁目前还没提交，也没有加到基础 YAML 和文档里。

### 6.2 其他
- `score_centering_head_mass` 只衡量 top-k 覆盖了多少采样质量，不反映 TIS 开关或修正量大小；崩溃时它会掉到 0.3 左右（分布变平），可作为退化信号。
- 步耗时：Qwen3-8B lag 4 约 120～130 秒，lag 0 约 200 秒。

## 7. 局限
1. 每个配置只有一个种子，差异小的比较（如 SC128 的 TIS 开/关）不能下结论。
2. reward 是训练集上的 math-verify 奖励，SingleController 目前没有验证循环，没有留出集结果（如 AIME）。
3. 实验之间不完全对等：Qwen3.5 的 top-p 实验用了 `top_k`；各组完成步数不同（321～500）；补丁和 `flat_logprobs` 在 Qwen3.5 的多数实验中是中途才开的。
4. 崩溃的原因没有被分离：lag、失配、策略熵塌缩、长度增长都可能参与，这里只有相关性证据。
5. 新指标只在 Qwen3-8B 的 exp3～6 中有数据；Qwen3.5 的旧实验没有，也无法补算（旧 checkpoint 只保留最后几个）。
6. 公式核对是对照代码和仓库文档进行的，我没有读论文原文（arXiv:2609.20807）。

## 8. 建议
1. 默认使用 **score centering + TIS 关**（exp5 的形式）；TIS 作为对比项保留。在这批实验里它最稳，TIS 开时 centering 又基本被抵消。
2. 关 TIS 后没有任何东西限制陈旧数据，建议监控 `gen_kl_error`、`weight_dev` 和 `train/weight_version_lag`，必要时降低 lag（如 4 → 1～2）或学习率。
3. 补做多个种子，并加入留出集评测，再判断 TIS 开/关和 top-k 的差异。
4. 加入显式校验：SC 要求 PPO ratio 的 clip 不会触发（例如要求一步一更新或 `force_on_policy_ratio`），清理 recipe 里空操作的 clip 参数。
5. 讨论是否在 score centering 里使用 `token_level_loss: false`，让归一化与公式的 `(1/G)Σ(1/T_i)` 一致。
6. 如果要 top-p，需要同时给出 `top_k`；目前没有看到收益，成本也更高。
7. 把"跳过候选解码"补丁和新指标整理进代码库（基础 YAML、reference configs、文档），并推动 vLLM 上游支持。

## 附录

### A. 新指标定义（`train/score_centering_tis_*`）
对每个 token 位置，把头部每个候选 id 当作假设被采样到的 token，按 `q` 加权，计算每单位 advantage 的 logits 梯度：
- TIS 关：`g(x) = (e_x − p) − (c_off − S_off·p)`；
- TIS 开：`g(x) = w_x·(e_x − p) − (c_on − S_on·p)`，`w_x = clamp(p_x/q_x)`。

| 指标 | 含义 |
|---|---|
| `grad_rms_off` / `grad_rms_on` | 两种模式下每 token 梯度的均方根 |
| `grad_rms_diff` | 两种模式更新向量差的均方根，衡量开关 TIS 对更新的影响 |
| `weight_dev` | `E_q|w − 1|`，TIS 对采样 token 项的平均重加权幅度 |
| `center_l1_off` / `center_l1_on` | centering 向量 `‖c − S·p‖₁` 的大小 |

只考虑头部，忽略尾部（约 0.2%～2% 的质量）。TIS 的界在没有配置时取 `(0, 2)`。实现：`nemo_rl/algorithms/loss/score_centering.py` 的 `compute_tis_effect_metrics`。
